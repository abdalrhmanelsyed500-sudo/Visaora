# Visaora technical SEO strategy

## Launch principles

Visaora is designed for organic growth, but not for a page-count race. No page is created or indexed to target a keyword unless it offers a useful, unique, source-backed experience. Country metadata and category taxonomy are present at launch for navigation; thin country/category landing routes use `noindex,follow` until they contain at least one published guide.

This is the intentional launch policy:

```text
Useful collection pages → crawlable navigation
Published country/visa content → indexable landing and guide pages
Draft/demo/empty/query/filter pages → noindex or excluded from sitemap
```

## Canonicals and URL policy

Canonical URLs are generated from stable lowercase slugs:

- `/countries/{country-slug}`
- `/countries/{country-slug}/visas`
- `/countries/{country-slug}/visas/{visa-slug}`
- `/categories/{category-slug}`

`next.config.ts` permanently redirects legacy singular `/country/*` and `/visa/*` forms. Filters are client state on the collection page rather than crawlable URL variants, so the application does not generate millions of query URLs. If SEO-worthy filtered views are needed later, promote only curated routes to first-class pages and give every other combination a canonical/noindex policy.

## Metadata

`src/lib/seo.ts` centralizes title, description, Open Graph, X/Twitter and canonical builders. Admin editors can override title/description/OG/canonical via `SeoMetadata`, but overrides must not bypass `noIndex` safeguards.

Templates:

```text
Home: {brand} — Explore Every Visa Pathway
Country: {Country} Visas — Explore Visa Types
Visa: {Visa} — Requirements, Eligibility & Application | Visaora
Category: {Category} Visa Pathways
```

Descriptions are short and honest. They do not claim a fee, processing time, eligibility rule or pathway exists when no source-backed content exists.

## Structured data

Used only when the underlying entity exists:

- `Organization` and `WebSite` in the root layout.
- `Country` and `WebPage`-appropriate entity context on country pages.
- `BreadcrumbList` on country, category and visa routes.
- `FAQPage` only when real, published FAQ rows are attached to a guide.
- `ItemList` on the country collection page for the rendered directory set.

No fake FAQ, review, rating, approval rate, popularity or government affiliation schema is emitted.

## Sitemap and robots

- `/sitemap.xml` is generated by `src/app/sitemap.ts`.
- It includes the home, useful collection/legal pages, published category pages, indexable country pages and published non-demo visa pages.
- Empty country/category routes are intentionally absent until content is published.
- `robots.txt` allows public pages, points to the sitemap and disallows `/admin`, `/api/` and `/internal`.
- Search pages are `noindex,follow`; they are not placed in the sitemap. They remain crawlable so normal user navigation is not blocked.
- Future scale can split output into `sitemap-index.xml`, `sitemaps/countries.xml`, `sitemaps/visas.xml` and `sitemaps/categories.xml` without changing the content predicates.

## Internal linking

The hierarchy is visible in HTML and breadcrumbs:

```text
Home → Countries → Country → Visas → Visa guide
Home → Categories → Category → Visa guide
```

Country pages link to the eight taxonomy categories and a small set of same-region countries. Visa pages will link to their country, category, explicit related visas/countries and source records. There is no full-graph link dump.

## Programmatic SEO guardrails

Before a future country or visa route is indexable, the publish service should check:

1. entity is `PUBLISHED` and not demo,
2. page has a unique canonical slug,
3. required content fields are present,
4. at least one official source is attached,
5. verification date is recorded,
6. page is not a duplicate or redirect target,
7. metadata is not an unedited duplicate of an unrelated entity,
8. rendered HTML is useful without client JavaScript.

The first release's tests assert that an empty US country route is not in the sitemap and is marked noindex. That is a quality gate, not a permanent rule: publishing the first reviewed guide turns the same route indexable.

## Search intent map

The search layer recognizes country names/ISO aliases and broad category intent (`student` → Study, `work` → Work, `tourist` → Visit). It does not manufacture visa names. When real guide entities arrive, the same interface can return country, category and visa results ordered by exactness.

Search and filter result URLs are interaction surfaces, not landing-page templates. Curated, useful intent pages can be added later under `/categories/{category}` or another reviewed route.

## Pre-publish technical checklist

- [ ] SSR HTML includes the page's useful content.
- [ ] Title and description are unique and within reasonable length.
- [ ] Canonical resolves to one lowercase URL.
- [ ] Open Graph and X card metadata resolve.
- [ ] Breadcrumbs match the visible hierarchy.
- [ ] JSON-LD reflects actual content only.
- [ ] Draft/archive/demo pages are noindex and absent from sitemap.
- [ ] Related links are intentional and not excessive.
- [ ] Official source links are visible and open safely.
- [ ] Mobile layout has no horizontal overflow.
- [ ] Page passes accessibility and performance checks.
